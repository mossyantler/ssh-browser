# SSH Browser development protocol v1

Native host: com.sshbrowser.helper. Messages are UTF-8 JSON with native-endian uint32 framing. requestId correlates replies. Replies: {requestId,ok:true,result:{...}} or {requestId,ok:false,error:{code,message}}. No secrets in messages or logs.

Host: {id,name,group,favorite,mode:'alias'|'manual',alias,address,port:22,user,keyPath:''}. For alias use existing SSH config. Manual uses optional absolute keyPath. No password or key data.

Native requests: hello {protocol:1,profileId}, connect {host}, release {tunnelId}, disconnect {}, status {}. hello returns {version:'0.1.0',protocol:1}. connect starts new tunnel without stopping existing one; returns {tunnelId,hostId,port,status:'ready',connectMs} where connectMs is milliseconds from SSH start through SOCKS readiness, including local port-collision retries. release stops one tunnel. disconnect stops all. status returns {tunnels:[{tunnelId,hostId,port,status}]}. Events: {event:'tunnel-exit',tunnelId,hostId,reason,code}; {event:'network-change',online:boolean}, sent once after hello with the current state and then after each debounced (500ms) change of online state or routable interface addresses, read from the macOS routing socket. online means an up, non-loopback interface has a global unicast address. SSH keepalive is ServerAliveInterval=5 with ServerAliveCountMax=3 (dead link detected within about 15s). EOF cleans all owned SSH child process groups.

Extension UI messages: {type:'GET_STATE'}, {type:'CHECK_HELPER'}, {type:'SAVE_HOST',host}, {type:'DELETE_HOST',id}, {type:'CONNECT',id}, {type:'LOCAL'}, {type:'STOP'}, {type:'IMPORT',hosts}. UI replies: {ok:true,state} or {ok:false,error:string,errorCode:string,state}. Native error.code is preserved. CONNECT/LOCAL/STOP and automatic connection attempts serialize; incoming explicit intent cancels automatic recovery before entering the queue. GET_STATE is not queued: it returns the live snapshot (including connecting/reconnecting) immediately. STATE_CHANGED:{type:'STATE_CHANGED',state} broadcasts status changes independently of UI request completion.

State: {hosts:[],profileId,status:'local'|'connecting'|'reconnecting'|'connected'|'error'|'disabled',activeHostId:null,error:null,errorCode:null,helperVersion:null,helperAvailable:null,setupErrorCode:null,proxyControlled:false,desiredMode:'disabled'|'local'|'remote',selectedHostId:null,currentPort:null,tunnelId:null,pendingRemote:null,reconnecting:false,retryAttempt:0,retryLimit:3,reconnect:null,networkOnline:null,connectionDurationMs:null}. networkOnline is the live helper's last network-change report and resets to null whenever the native client changes or is lost. connectionDurationMs is the helper's connectMs for the current connected route and is null otherwise. local means explicit direct mode. disabled means extension proxy override cleared; underlying OS/policy/other-extension setting applies. storage.local persists hosts/profileId/desiredMode/selectedHostId/currentPort/pendingRemote/reconnect; no sync. Native port is held by the service worker, not the popup.

CHECK_HELPER checks hello protocol 1 only. With an initialized live native client it uses the cached hello result; otherwise it opens a separate hello-only session and closes it. It never requests connect, release, disconnect or changes proxy settings. helperAvailable is null before inspection, true after compatible hello, false on hello/native failure. Losing an already initialized native port (NATIVE_LOST) does not change helperAvailable/setupErrorCode; the next hello decides availability. setupErrorCode is null on success or an open error-code string: PROTOCOL, NATIVE_UNAVAILABLE (missing/unusable native registration), NATIVE_TIMEOUT, or the original native error.code. Failure returns ok:false/error/errorCode/state and broadcasts STATE_CHANGED without changing routing mode.

SAVE_HOST and IMPORT reject changes to in-use connection fields atomically: mode plus alias for alias mode; mode/address/port/user/keyPath for manual mode. In use means activeHostId or desiredMode remote plus selectedHostId, including recovery/error states. name/group/favorite can change. Unused fields of the other connection mode do not alter the live connection. Deleting an in-use host is rejected.

UI normal extension uses chrome.runtime.sendMessage; preview uses localStorage and is visibly labelled UI preview, no real SSH. No fabricated live-connection claims. Default preview no hosts. Popup rapid select; options host CRUD/group/search/favorite + selected status. Korean interface. Permissions: storage,proxy,nativeMessaging,alarms only as used. incognito:not_allowed. No host_permissions or content scripts.

## Crash-safe switching (implemented)

Before any candidate SOCKS proxy change, persist pendingRemote:{hostId,tunnelId,port}. Startup treats any marker as remote-required even if the previous desiredMode was local/disabled, and installs SOCKS 127.0.0.1:9 as a blocker. Commit desiredMode/selectedHostId/currentPort and marker removal in one storage write. A failed rollback retains uncertain candidate metadata and cleanup always releases the candidate or closes the native port; never report old/connected without a confirmed live route. An existing live A connection is preserved if switching to B fails and rollback is verified.

## Bounded remote recovery

Unexpected native loss or a selected tunnel-exit after a committed remote connection installs and verifies SOCKS 127.0.0.1:9 before waiting to reconnect the selected host. Remote worker startup also replaces the stored tunnel port with this blocker; saved connected status is never trusted. Backoffs are 1s, 3s, 8s with at most three automatic attempts. retryAttempt counts attempts already started, including during backoff; retryLimit is always 3. While reconnect.nextRetryAt is set the UI labels the pending attempt as retryAttempt+1. A blocker already verified at port 9 is not rewritten between attempts, and SSH-level retry failures keep the healthy native helper. A failed LOCAL/STOP that leaves the remote route live keeps automatic recovery enabled. While reconnecting, network-change online:true pulls a future nextRetryAt to now without changing the attempt budget. While the live helper reports online:false, a due retry consumes no attempt and is deferred by 60s (re-checked in case an event is lost); network-change never touches a connected route, whose loss is left to SSH keepalive. status reconnecting/reconnecting true covers both waiting and connecting. Exhaustion remains remote/error with the blocker; LOCAL explicitly uses DIRECT and STOP clears only this extension's override.

Durable reconnect:{hostId,attempt,nextRetryAt,blocked,generation} is stored before wake scheduling and its attempt is incremented before native hello/connect. A reservation interrupted by worker death still consumes that attempt. Successful automatic recovery retains the consumed count with nextRetryAt:null; restart or another loss cannot reset it. Only a successful explicit CONNECT resets this budget to zero. LOCAL/STOP clear reconnect. Missing legacy records can initialize one bounded budget; malformed or exhausted records cannot authorize more attempts.

An eager timer and chrome.alarms share this durable deadline; alarms wake a suspended MV3 worker and are recreated from storage on restart. Browser scheduling can delay wake beyond the requested backoff. Repeated/stale alarm or timer delivery cannot create an extra attempt after success/cancellation. LOCAL, STOP and manual CONNECT immediately invalidate the generation and clear scheduled wakes; late automatic replies cannot commit an obsolete remote route. Tunnel and proxy operations remain serialized.

Automatic recovery allows only transient NATIVE_LOST/NATIVE_TIMEOUT/TIMEOUT/SSH_EXIT/SSH_CONNECT/NETWORK failures. The helper classifies refused, unreachable, unresolved and reset connections as NETWORK; unclassified connect failures stay SSH_CONNECT and are retried only within the automatic budget for a host that already connected once. AUTH, HOST_KEY, INVALID_HOST, PROTOCOL, missing native helper, unknown errors, external PROXY_CONTROL, and uncertain pendingRemote/rollback are fatal and do not schedule retries. The native tunnel-exit code can be a numeric process exit code; its classified reason AUTH/HOST_KEY/TIMEOUT/NETWORK/SSH_EXIT determines retryability. External proxy ownership is reported without attempting automatic takeover. A first explicit CONNECT from local/disabled that fails before proxy changes leaves its prior routing in place and does not start recovery. Uncertain pendingRemote is retained for explicit resolution and never automatically retried.

Native helper disables OpenSSH master multiplexing (-S none, ControlMaster=no, ControlPersist=no) and ForkAfterAuthentication so it owns the tunnel process. Explicit LOCAL means DIRECT; STOP clears our override only. Toolbar badges: SSH / LOC / ! / connecting indicator, with current host in action title. Host deletion uses a DOM dialog, not a system confirm box.
